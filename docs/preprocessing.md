# SmartKhet 2.0: Big Data Preprocessing & Cleaning Pipeline

## 1. Pipeline Overview

The SmartKhet 2.0 Big Data preprocessing engine bridges disparate spatial-temporal agricultural datasets into an integrated, analysis-ready tabular dataset.

The pipeline executes sequentially via eight modular scripts located in `backend/data_pipeline/`:
1. `01_acquire_datasets.py` — Provenance logging and registration.
2. `02_inspect_datasets.py` — Automated distribution, outlier, and missing-value profiling.
3. `03_generate_demo_dataset.py` — Climatologically authentic multi-year baseline dataset.
4. `04_preprocess.py` — PySpark / Pandas schema validation, gap interpolation, and derived variables.
5. `05_feature_engineering.py` — Lag generation, rolling windows, cumulative rain, and target definition.
6. `06_validate_pipeline.py` — 8 automated quality & anti-leakage gates.
7. `07_train_model.py` — Chronological splitting, scaling on train only, RF & XGBoost training.
8. `08_generate_reports.py` — Static HTML & JSON audit reporting.

## 2. Transformations Applied

### 2.1 Deduplication
- **Constraint:** $(farm\_id, date)$ forms a natural unique key.
- **Rule:** If duplicate date records exist for the same grid-point, the first record is retained and redundant rows are purged and logged to the audit trail.

### 2.2 Missing Value Treatment & Imputation Policy
- **Gaps $\le 3$ Days:** Forward linear interpolation along the time dimension per farm.
  $$\theta_t = \theta_{t_0} + \frac{t - t_0}{t_1 - t_0} (\theta_{t_1} - \theta_{t_0})$$
- **Gaps $> 3$ Days:** Maintained as `NaN` or excluded entirely. No synthetic or mean-fill values are fabricated, preventing false statistical confidence.

### 2.3 Unit Standardization
- Precipitation: Standardized to daily millimeters ($\text{mm}/\text{day}$).
- Temperature: Converted from Kelvin ($K$) to Celsius ($^\circ\text{C}$): $T_C = T_K - 273.15$.
- Soil Moisture: Converted from percentage (%) to volumetric water content ($\text{m}^3/\text{m}^3$, $[0.0, 1.0]$).

### 2.4 Target Leakage Prevention
To guarantee that the machine learning models cannot cheat during evaluation:
- Target variable $\text{SM}_{t+1}$ (`soil_moisture_next_day`) is generated by a negative shift ($-1$).
- The last observation per farm is dropped because its next-day value is unobserved.
- All lag features strictly use indices $\le t$.
- Preprocessing transformations (such as `StandardScaler`) are fitted strictly on the $70\%$ training partition.
